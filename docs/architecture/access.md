# 访问策略与 P2P 预留（Access & P2P）

> 承接 [`storage.md`](./storage.md)。定义**可见性档位**、密钥分发、信任根，以及为 P2P 预留的接口。
> 核心立场：**不追求"绝对防住一切"，而是把威胁收敛为有限几档，逐档用对等的密钥机制。**

状态：**草案 v0.1**

---

## 1. 一句话模型

> 存储是数据流，传输也是数据流；每个对象归属一个**空间**，空间的**可见性档位**决定"谁能读、谁能发现、密钥怎么给"。

---

## 2. 四档可见性

| 档位 | 谁能读 | 谁能发现 | 密钥机制 | 去重范围 |
|---|---|---|---|---|
| **私密** private | 仅本机 | 无人 | 随机 SK，MK 封装 | 库内 |
| **公共** communal | 网络成员 | 网络内 | **共享密钥**：组密钥，wrap 到成员 X25519 | 网络内 |
| **公开** public | 任何人 | 任何人 | **公开密钥**：已发布/非秘密，或明文 | 全局 |
| **定向** direct | 指定对端 | 双方 | 每对象 CK，wrap 到收件人 X25519；或 PSK | 基本无 |

要点：

- **公共 ≠ 公开**。公共是"成员才拿得到密钥"（共享密钥）；公开是"谁都可能拿到"（公开密钥/明文）。
- 去重范围随档位自然收敛：密钥可见性 = 去重边界，**不会**因加密产生跨档确认攻击。
- 档位是**策略**，可随时在受控条件下升降级（涉及重加密，见第 6 节）。

---

## 3. 身份与信任根

### 3.1 身份

- 每库一对密钥：**Ed25519**（签名，作者证明）+ **X25519**（密钥协商，接收封装）。
- 公钥即网络标识（peer id = 公钥短哈希）；私钥种子由 MK 封装，解锁后可用。

### 3.2 信任根

- 每个 manifest 由作者 Ed25519 私钥签名（`author` + `sig`），并以 `prev` 串成**哈希版本链**。
- 对端同步时：**验签 → 验链 → 才应用**。任一不通过即拒收该版本。
- 信任启动：首次获取某作者公钥的途径（扫码/邀请/介绍人）待定，属发现层。

---

## 4. 密钥分发（按档位）

### 4.1 私密

- SK 随机生成，用 MK 封装存于空间记录；不出库。

### 4.2 公共（共享密钥，成员可读）

- 组密钥 SK 分发给成员：对每个成员的 X25519 公钥，用 **ECIES 式封装**（临时 X25519 → HKDF → AEAD 包住 SK）。
- 成员变更 → **密钥轮换**：新 epoch 的 SK 只加密新写入；旧 epoch 密钥按需重封装（懒轮换，见第 6 节）。
- 空间记录本身只含"封装后的 SK + 成员列表"；不持有 SK 者无法解密内容。

### 4.3 公开（公开密钥，任何人可读）

- SK 为**公开密钥**（可发布、可从公开种子派生）或内容直接明文。
- 目的：真正可公开的博客/站点内容；且公开空间可**全局去重**（同内容全网一份）。

### 4.4 定向（点对点）——双机制并存

- **默认·非对称封装**：每对象随机内容密钥 CK；用收件人 X25519 公钥封装。无需预先共享秘密，可对多人分别封装。
- **可选·预共享密钥(PSK)**：双方提前约定口令/分享码，`Argon2id(口令) → KEK` 封装 CK。
  - **坦白的代价**：PSK **无前向保密**；口令弱则可离线暴力；密钥复用/泄漏影响面大。故 PSK 定位为**便捷分享手段**，非默认。
- 定向发送一个属于私密空间的对象时，需**重打包**（把明文用 CK 重新加密进"定向空间"）；代价是该副本不参与去重，可接受。

---

## 5. P2P 预留（数据面接口，暂不实现网络）

存储层已为下列能力留好形状，网络层落地时无需迁移数据：

1. **寻址**：CID 即块地址；"want list = 一组 CID"是最小传输原语（类 BitTorrent）。
2. **对象即流**：manifest 的有序块表 = 可分段、可并行、可续传的流。
3. **增量**：FastCDC → 只传变化的块；断点续传按块。
4. **校验**：逐块 AEAD + CID 重算；manifest 验签 + `prev` 链。
5. **共享**：空间 = 授权与去重的单位；公开空间全局去重，公共空间网络内去重。

**未决（发现/传输/同步层，后续文档）**：节点发现（mDNS/DHT/介绍）、传输（Noise/TLS over QUIC）、NAT 穿透、同步协议与冲突合并、垃圾回收在分布式下的引用保留。

---

## 6. 密钥轮换与档位变更

- **轮换（空间内）**：引入 **key epoch**。块记录其 epoch；新写入用新 epoch 密钥；旧 epoch 密钥保留以读旧块，按策略懒重封装或重加密。
- **档位变更**（如 私密→公共）：
  - 升"更公开"：把 SK 以目标档位方式重新分发（如 wrap 给成员），块无需重加密。
  - 降"更私密"：**必须重加密**（旧密文/已分发密钥无法收回），生成新 SK 并重写块。
- 明确：**已泄漏的密钥无法追回**，只能轮换止损。

## 7. 威胁模型（主动收敛）

**我们只承诺防住这几类场景：**

| 场景 | 手段 |
|---|---|
| 磁盘被拷走 | 静态密文 + keyed CID 文件名 |
| 传输被中间人截获 | 内容 AEAD；密钥不经明文信道 |
| 内容被篡改 | AEAD tag + CID 重算 + manifest 验签 |
| 非成员窥探公共内容 | 共享密钥仅成员持有 |
| 假冒作者发布 | Ed25519 签名 + 版本链 |

**明确不防（承认边界）：**

- **流量元数据**：谁连谁、传了多少、何时传。要藏需 PIR / 洋葱路由，属更后面。
- **解锁态终端被攻陷**：内存取证、键盘记录、恶意进程。
- **弱口令离线暴力**：仅靠 Argon2id 参数抬高成本。
- **已授权成员的二次泄漏**：成员拿到明文即可外传（DRM 问题，无解）。
- **组密钥成员变更时的窗口期**：轮换前的旧密钥仍可解密旧数据。
