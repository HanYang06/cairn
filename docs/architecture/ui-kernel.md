# UI 内核（UI Kernel）设计 · 总纲

> 定位：**UI 内核 ≠ Qt**。Qt 只是实现材质；内核负责「对象 → 界面」的**生成、编译、绑定、配置**。
> 关系：数据内核对侧见 [`data-model.md`](./data-model.md) / [`storage.md`](./storage.md)；
> 横切设施见 [`kernel.md`](./kernel.md)；主题 / 配置细则见 [`ui-theme.md`](./ui-theme.md)（待重写）。

状态：**草案 v0.1**。技术路线已定（Widgets 宿主 + QML 岛）；直通 / 生成 / 绑定 / 配置为设计目标，
分阶段落地，未实现处标「预留」，不假装已存在。

---

## 0. 一句话

**给一个领域对象，UI 内核自动长出一棵可用的界面树（模板），开发者只补细节；
数据变更由内核预埋的信号代理单向流到界面。**

它要解决的三件事（外加一套统一配置）：

1. **数据直通**：写 UI 时不必关心数据内核提供了什么，正常用即可。
2. **快捷创建**：加对象 / 加界面不该是重活；先自动生成，再改。
3. **事件绑定**：内核统一提供，声明 + 编译，不手连信号。
4. **统一 Config**：主题样式 + UI 配置，一套文件，比 CSS 轻。

---

## 1. 定位与边界

- UI 内核是 **Qt 之上的应用框架**，不是控件库；机制由内核给，页面 / 外壳由 app 组合。
- **技术路线：QtWidgets 宿主 + QML 岛**（画布 / 大规模关系图 / 特殊视觉）。
  判据：Qt 只支持 Widgets 里嵌 Quick，不支持 Quick 里嵌 Widgets，**宿主只能是 Widgets**。
- **领域专向，不求外部框架式极致通用**：领域已知（note / project / canvas / asset / group），
  该特化就特化，不做通用到无法维护的抽象。
- **各司其职（Web 式分工）**：领域对象除了结构 / 事件，还**对外声明 UI 可消费的契约**
  （字段 / 动作 / 信号）；UI 按契约绑定与生成。**契约是领域的事，渲染是 UI 的事**，不互相越界。
- **总目标（唯一尺度）**：**更便捷、更快、更轻量、更少工作量**地完成 UI 开发；
  任何机制与这条冲突即砍。
- **单向数据流**：内核 → 投影 → 视图；视图 → 意图 → 命令 → 内核。
  **不做响应式框架、不做依赖追踪、不做 diff / reconciler。**

## 2. 分层与依赖方向

```
app        页面 / 外壳（只写组合）
   │
ui.kernel  UI 内核：对象生成 · 描述编译 · 投影 · 绑定 · 配置
   ├─ facet      交付单元：对象 → UI 定义（生成 + 绑定）
   ├─ projection 对象 → 视图模型（纯数据，Qt-free）
   ├─ bridge     内核信号代理 → Qt 信号
   ├─ binding    意图 / 命令表
   └─ config     Theme（封闭）+ UiConf（开放）
   │
PySide6    Qt 实现材质（Widgets 宿主 + QML 岛容器）
   │
core / feature   数据内核（Qt-free）
```

**红线（用 import 图钉死，不只写在文档里）**：

```
ui  →  core.types（中立 DTO / Oid） + 领域契约
ui  ✗  core.storage（Bucket / Block）   ← 永远不许
ui  ✗  feature                          ← 永远不许
ui  ✗  Vault 的内部（body / attrs / checksum / catalog …）
```

- **Bucket / Block 是存储实现，与 UI 八竿子打不着**：UI 不 import、不复用、不感知。
  它们回答"字节怎么存 / 去重 / 版本化"；UI 回答"对象长什么样 / 能做什么 / 变了怎么通知"，两者正交。
- UI 代码里一旦出现 `bucket` / `block` / `body` / `attrs` / `checksum` / `type=cairn.note` 即失控。
- **新开发者判据**：要他看懂 UI 必须先学 Bucket / Block —— 这设计就已经错了。
  他的心智模型只该是：**领域对象 → 契约 → 界面**。
- 数据内核 **不 import Qt**；领域对象不认识界面。
- 加一条架构测试断言 `ui` 不 import `core.storage` / `feature`，比任何文档都管用。

> 与旧规则「UI 不 import feature / 不碰 Vault」同向，这里把边界写死：
> UI 只消费 **中立类型 + 领域契约 + 投影**，写回只经**命令**。

> 目录预埋（2026-09-19，**空目录**）：`src/core/signal/`（Qt-free 信号原语）与 `src/ui/core/`（UI 内核）。

## 3. 支柱一：数据直通

### 3.1 信号代理：内核在变，UI 不变

- **内核必然一直变**（业务 / 数据变 → 内核变），但 **UI 可以不变**。挡在中间的就是**代理**：
  UI 只对代理编程，内核变更由代理适配，UI 不跟着动。**代理是稳定面。**
- **两端各有一个代理**：
  - **数据侧**：`core.signal.Signal` 包住内核（领域体系），对外是稳定面，也是**取实体操作的入口**
    （拿不到实体就无法操控）。它**不生成页面**——生成页面是 `Facet` 的事。
  - **UI 侧**：Qt 的信号槽是另一端的接口，同样包成同构代理，否则无从谈绑定。
- **绑定（`Bind`）把两个稳定面接起来**——所以「绑定对象」是**必然存在**的，不是可选装饰。
- 变更流向：`内核 → 数据侧代理 → Session（投影缓存）→ UI 侧代理 / Bridge → Qt 信号 → 部件`。

#### 3.1.1 `core/signal` = 现有事件总线的升级（不重造）

底座就是 `core/events.py` 的 `EventBus`（`emit` / `subscribe`），它已有的投递语义正好用：
**提交后、同步分发、异常隔离、不可重入**。在它之上分两层：

| 层 | 内容 | 例子 |
|---|---|---|
| **存储事件（已有）** | 块级事实：`ObjectPut` / `ObjectDeleted` | "某个块被写 / 删了" |
| **语义信号（新增）** | 各域声明的"人话"通知 | project 喊 `cairn.project.members.changed` |

四个动作：**声明**（域说会喊哪些话 / 关心哪些话）、**喊**（`emit(名字, 数据)`）、
**听**（`subscribe(名字, 处理)`）、**送**（走老总线，规则不变）。

- **域之间不 import，只认信号**：note 不认识 project，但听得懂"成员变了"。
- 听的人**不缓存假设**，听到就**重新读当前状态**——"邻居突然变奇怪"因此不致命。
- 喊话的人**不等回复**（通知，不是命令）；处理器里别再乱喊（沿用「不可重入」）。
- `Signal(Note)` 就是域对外暴露的**信号 / 动作句柄**（§3.3 的 `signals`）。
- **信号名字 = 公共函数名 + 命名空间前缀**：因为挂在公共总线上，必须**不撞名**——统一写
  `cairn.<域>.<什么变了>`（如 `cairn.project.members.changed`），不用裸 `changed`；
  并在契约里**登记**（别人能查、UI 能校验）。
- **数据格式 = 领域自己定的那份**：**没有"UI 与领域之间的另一套格式"**；唯一要求是普通领域数据
  （不是 Block / 存储对象）、且**声明**出来，听的人才知道会收到啥。
- 预埋目录 `src/core/signal/`（Qt-free，待实现）。
- 批量写入需抑制逐条通知、收尾发一条汇总（预留）。

### 3.2 投影（Projection）

- 对象**不直接塞进 Qt 模型**；先投影为**类型化视图模型**（row / DTO），再渲染。
- 投影按需缓存；变更通知到达时按 `oid` 失效重算。
- 写回一律走**命令**（见支柱三），不直接改对象。

### 3.3 领域契约（各司其职）

领域对象除了结构 / 事件，还要**对外声明 UI 可消费的契约**——这是"各司其职"的落点，也是 Web 式前后端分工：

| 契约项 | 内容 | 谁提供 |
|---|---|---|
| **fields** | 有哪些字段、什么种类、展示 traits（标签 / 分组 / 可编辑性 / 展示类型） | 领域声明，中立投影 |
| **actions** | 支持哪些语义动作（收藏 / 归档 / 复刻 / 删除 …），参数与可用性 | 领域声明 |
| **signals** | 变更通知（存储事件 + 本域语义信号） | 内核 + 领域 |

- **契约是领域的事，渲染是 UI 的事**：领域只说"我有什么"，UI 决定"长什么样"。
  领域**不指定控件、不碰 Qt、不管像素**。
- 契约**不得长在 `Block` 上**：字段描述符（`Attr` / `Data`）属存储机制的一部分，**不外泄给 UI**；
  在内核边界内投影成中立 `FieldSpec{名字, 种类, traits}`，UI 只读 `FieldSpec`。
  "派生"发生在边界内，UI 看不到来源。
- **字段本身从领域对象分析而来，不写死**：UI 分析领域，知道它有哪些字段、什么类型；领域后来加字段，
  UI 跟着长出来（**信号**告知"它现在有哪些"）。
- **四词只是"显示提示"的可选槽位**：`label`（显示名）/ `group`（分组）/ `display`（控件；缺省按类型映射）/
  `editable`（只读 / 可编辑 / 隐藏）；**值随领域、能推的省略**——不是写死字段，是写不写这几条提示。
- 没有契约的领域也能显示（退化到裸对象）；契约是**加性**的，逐步补。
- UI 按契约名字机械绑定 / 生成，**不用翻领域代码、不用猜**。

### 3.4 直通的前提（数据内核配合）

要让「加一个字段，界面自动有」成立，数据内核须补齐：

| 事项 | 现状 | 目的 |
|---|---|---|
| **字段内省（中立投影）** | 缺（类型信息只在 `Block.__init_subclass__` 内部消费，见 `core/storage/block.py:318`） | 内核边界内产出 `FieldSpec`，**不外泄 `Attr` / `Data` / `Block`** |
| **字段 traits（纯数据）** | 缺 | 展示语义随契约声明，**不 import Qt** |
| **`core/signal` 语义层** | 缺（现有 `EventBus` 只有块级事件） | 域间"人话"通信 + UI 代理同源 |
| **facade 收口** | `Vault` 仍有死 API（`put` / `put_meta` / 单版本占位） | UI 只见稳定接口 |

## 4. 支柱二：快捷创建（对象驱动生成）

这是本设计的关键，也是与"手写每个界面"最大区别所在。

```
领域契约 (fields / actions / signals)
        │  ① 读取契约（经中立投影）
        ▼
   UI 结构（自动生成，可用的初稿）
        │  ② 套通用架构 + 补默认行为
        ▼
   开发者只改细节（增 / 删 / 换）
```

> **交付单元 = `Facet`**：一个域的整套 UI 定义；`__init__` 只干两件事——**属性配置 + 绑定**。
>
> - **自包含**：主题等内置属性由 `Facet` 自带。
> - **不自包含**：布局 / 部件必须自己 import、选、配好再放进来；它们的**专属配置属于它们自己**
>   （导入后先改，得到新对象，再 `set` / `add`）。
> - **`set` = 设形态**（"你是什么"）：`layout.set(Grid)`。
> - **`add` = 加持有**（"你装了什么"）：`layout.add((1, 2), Editor)`。**两者语义不可混。**
> - **产物**：编译后得到的就是**对象本身**（`Facet` / 它的包装对象，完整描述结构 + 样式），
>   **直接甩给 App**；App 加载、挂上，结束。**不序列化、不加中间格式**——是啥传啥。
>   定义被动，编译 / 挂载在外部发起。
> - `Page` 退回为**内层页面层**。

### 4.1 自动生成的产物

1. **默认行为（必然项）**：应用已有一套**通用大架构**（标题栏 / 活动栏 / 导航 / 内容 / 检查器 …），
   是"必然存在"的部分。对象接进来，自动挂上：页面形态、保存 / 版本检查点、选中、搜索索引、
   事件订阅、生命周期。
2. **结构初稿**：按对象类型给默认页面形态（列表 / 详情 / 画布）；
   字段按**类型映射表**给默认控件（`str→单行输入`、`bool→开关`、`dict→KV 编辑器`、
   `list[oid]→引用列表`、`Canvas→QML 岛` …）。
3. **细节（工作量本身）**：布局微调、专用控件、交互细节——**系统不知道，就不猜**。
   自动生成的永远只是**初稿**，不假装细节已实现。

### 4.2 原则

- **特化优于通用**：领域已知，直接做特化，不做过度抽象。
- **生成的仍走同一套编译**（见 §4.3），生成与手写同构：初稿 = 一棵结构，
  改初稿 = 改结构节点，再一次性编译成 Qt 树。
- **加字段 ≈ 只在领域声明一处；加控件 ≈ 只在原子目录加一处。**
- **验收指标**：加一个领域字段 = 领域一处（+ traits），UI **0~1 处**；加一个标准动作 = 契约一处，
  通用 UI 自动出现。**若加字段还要改 5 个 UI 文件 → 设计失败，回去改契约。**

### 4.3 描述编译（生成与手写的共同底座）

- 结构 → Qt 树，**单向编译一次**；扩展只加 translator（注册表），`Raw` 是一等逃生舱。
- **不造 reconciler / 不搬响应式**：响应仍走 信号代理 → Session → 模型。
- 结构词汇只分两类：**布局组织器**（纯几何：Box / Grid / Split / Stack）与
  **组件 / 页面**（原子 + 组合 + 页面）；增长只在原子与页面，外壳稳定。
- **QML 岛 = 普通原子**：不是外壳、不是完整 UI，是**特定领域的增强组件**（画布 / 大关系图）；
  外面包一层（`QQuickWidget`），对外只露"配置进 / 信号出"，**接法与普通部件完全一致**
  （`bind.add(岛.某信号, 域信号)`）；Facet 作者甚至不必知道它是 QML。

> 与已废弃的 `decl` 关系：问题域相同，取舍继承（单向编译、translator、Raw、不造响应式），
> 实现另行立项。旧记录见 `.agents/skills/memory/references/decisions.md`。

### 4.4 多页面（`Facet` 里的 `Page`）

一个域不可能只有一页（note：列表 / 编辑 / 关系 / 历史）。所以在 `Facet` 里加一层 **`Page`**：

- **`Page` = 单个页面**：一个布局 + 部件 + 绑定，是导航的一个目标。
- **`Facet` 持多个 `Page`，并声明怎么切**（`tabs` / `stack` / 主从）；默认 `tabs`。
- **单页域不必显式写页**：`Facet` 自己就是默认页，直接 `self.layout.set(...)`。
- 宿主（页签 + 堆叠）由 **App 提供**；页面**首次显示才构建**（懒加载），切换触发 `on_enter` / `on_leave`。

```python
class NoteFacet(Facet):
    def __init__(self):
        super().__init__(Note)                    # 默认页：直接写
        self.layout.set(Table)
        self.add((0, 0), Title)

        edit = self.add_page("edit", title="编辑")  # 再加页
        edit.layout.set(Grid)
        edit.add((0, 0), Editor)

        self.navigate(mode="tabs")                # 怎么切页
```

## 5. 支柱三：事件绑定

### 5.1 事件从哪来（Qt 侧机制，作者不碰）

- **物理层**：鼠标 / 键盘 → `QMouseEvent` / `QKeyEvent` → 控件的 `event()` /
  `mousePressEvent()` / `keyPressEvent()`。
- **控件层**：Qt 控件已把常用物理事件提炼成**信号**（`clicked` / `pressed` / `textChanged` /
  `returnPressed` …）；Qt 原生连接是 `sender.signal.connect(slot)`。
- **统一化**：UI 侧代理把「物理事件」与「控件事件」**都包成同一种 `Signal`**；
  自定义控件 / 手势才需自己从 `event()` 提成 `Signal`。Facet 作者**只面对 `Signal`，不碰 `QEvent`**。

### 5.2 `Facet.__init__` 只声明两件事

`Facet` 是**一个域的整套 UI 定义**（布局 + 部件 + 绑定）；`__init__` 里只写：

1. **属性配置**（改属性）
2. **绑定**（只声明，不在此刻 connect）

```python
class NoteFacet(Facet):
    def __init__(self):
        super().__init__(Note)          # 认领域；基类持有 self.note = Signal(Note)

        # ① 属性配置
        self.layout.set(Grid, rows=4, cols=4)
        self.add((0, 0), Title)
        self.add((1, 2), Editor)

        # ② 绑定（声明）
        bind = Bind(self)
        bind.add(self.save_btn.clicked, self.note.favorite)   # UI 信号 → 领域动作
        bind.add(self.clear_btn.clicked, self.on_clear)       # UI 信号 → 本类方法
```

- `self.save_btn` 是**描述节点**，不是活控件；`.clicked` 是它声明的信号。
- `self.note = Signal(Note)` 由 `Facet` 基类持有（一个域一个代理）。
- 真正的 `connect` 在**编译 / 挂载**时由 `Bind` 应用。

### 5.3 `Bind` 模型

- `Bind(self)`：绑定登记处，**作用域 = 该 Facet**，随生命周期自动释放。
- `bind.add(source: Signal, target)`：
  - **source** 是 UI 侧信号，**明确到信号**（`self.save_btn.clicked`），不做隐式主事件。
  - **target** 可以是**领域 `Signal`**（`self.note.favorite`）或**本类方法**（`self.on_clear`）——
    UI→内核 与 UI→UI 用同一种写法。
  - **参数沿 source → target 传递**；签名不匹配 / 信号名不存在，**编译期报错**。
- 两边都是事先定好的词汇（控件信号表 + 领域契约信号表），所以校验能做到编译期。
- **绑定是声明 + 编译**；**不是双向绑定，也不是响应式运行时**。
- **事件与转化分开看**：信号**带着数据来**；UI 收到后**能用就直接用，需要转换就用自己的方法转**
  ——转换是 UI 自己的事，不是内核规定的。
- **单一通路**：一个数据变化只有一条通知路径；一个用户动作只有一条命令路径。

## 6. 支柱四：统一 Config

**格式 = JSON**。两层，各有明确分工：

| 层 | 词表 | 管什么 | 真源 |
|---|---|---|---|
| **Theme** | **封闭** | 外观：色 / 圆角 / 间距 / 字号 / 字体 / 动效 / 阴影 | 外观唯一真源，组件只引用 `token.*`，禁硬编码 |
| **UiConf** | **开放** | 组件 / 页面的行为与配置，随组件生长 | 支持新增 / 覆盖 / 重定向 / 失效 |

- **顶层 `token {…}`** 管全局外观（颜色等）；其余是**具体配置**：`note.<…> = 值` / `note.<…> {…}`。
- **App 自动生成 JSON schema**：它认识所有 `Facet`，顺着就能知道有哪些域 / 部件 / 布局 / 属性，
  于是合法配置键**自动列出来**（IDE 可校验 / 补全），写起来轻松。
- 部件 / 布局的属性都在此呈现，**包含布局参数**——布局可自由拖动，参数落这个文件；
  **用户改界面不动代码**。
- 重叠处用 **「属性设状态、样式选状态」** 的伪状态桥缝合。
- 加载即校验（schema），未知段 / 键**报错**，不静默失效。
- 应用级设置（最近打开、键位、界面状态）**独立存放，不进 bucket**（非领域偏好）。

---

## 7. 与数据内核的关系（小结）

- **方向**：数据内核是底座（Qt-free、传输无关）；UI 内核只读经投影、只写经命令。
- **正交**：UI 内核不感知存储实现（Bucket / Block / pack / catalog / 内容池一律不可见）。
- **协作点**：领域契约（fields / actions / signals，经中立 `FieldSpec` 投影）、信号总线（通知）、
  命令（读写）。

---

## 8. 不变量（红线）

1. **UI 只消费中立类型 + 领域契约 + 投影**：**不 import `feature`，也不 import `core.storage`
   （Bucket / Block）**；数据内核不 import Qt。
2. **契约不得长在 `Block` 上**；UI 代码不得出现 `bucket` / `block` / `body` / `attrs` /
   `checksum` / `type=cairn.note` 等存储词汇。
3. **单向数据流**：内核 → 投影 → 视图；视图 → 意图 → 命令 → 内核。
4. **不做响应式框架 / reconciler**；绑定是单向编译。
5. **不改 `Block` 顶层字段**；UI 不感知存储结构。
6. **自动生成只产出初稿**；未实现的细节不假装存在（不可用项显式标灰 / 不展示）。
7. **外观只来自 Theme**；组件内禁硬编码颜色 / 间距 / 圆角。
8. **`set` 与 `add` 语义不可混**（设形态 / 加持有）。

## 9. 分阶段（草案）

| 阶段 | 内容 | 出口 |
|---|---|---|
| **M0 地基** | `core/signal`（含语义层，建于 `EventBus`）；`FieldSpec` 中立投影 + 契约；投影 / 模型；Config（JSON + 自动 schema） | 壳外可测的投影链路 |
| **M1 外壳** | App / MainWindow / Component / Panel / Page + 布局组织器 + 描述编译 + `Facet` | 三栏外壳可跑 |
| **M2 生成** | 对象驱动生成器 + `Facet(Note)` 特化初稿 → UI 结构数据包 → App 加载 | 用 note 打穿完整闭环 |
| **M3 扩展** | Project / Canvas；QML 岛（画布 / 大关系图） | 多领域复用同一机制 |

> 每阶段以 **note 打穿闭环**为准，不铺开半成品。
