# 网络层（P2P 底层）规格

> 承接 [`storage.md`](./storage.md)（内容寻址对象池）与 [`access.md`](./access.md)（身份/档位）。
> 定位：**网络是增强层，不是本体**。本地永远可用；联网只是把对象池连起来。

状态：**草案 v0.1**（先定底层协议与选型，实现分阶段）

---

## 1. 分层视图

```
应用/服务层      同步、博客、社区治理        ← 上层（后做）
────────────────────────────────────────
数据面协议       want / manifest / chunk     ← 本文件核心
节点角色         server（中心化·联邦共享） · peer（去中心化）
传输 / 安全      py-libp2p + Noise/TLS
发现 / NAT       mDNS · bootstrap · DHT · AutoNAT · Relay v2 · DCUtR
编址             CID(块) · (author, oid)(对象)
身份             Ed25519 签名 + X25519 协商（已有）
存储             内容寻址对象池（已有）
```

**关键：底层已经就位。** 池是内容寻址的，P2P 只需回答"我要这些 CID，你有没有？"——这是最小原语。

---

## 2. 编址

| 目标 | 地址 |
|---|---|
| 块 | `CID`（keyed BLAKE3，空间内去重） |
| 对象 | `OID`（ULID）+ `author`（公钥）→ 全局唯一 |
| 对端 | libp2p `PeerID`（由身份公钥派生） |

- 内容寻址使"任意节点都能提供任意块"成立，无需中心目录。
- 对象归属空间；档位（私密/公共/公开）决定**谁可请求、谁可提供**。

---

## 3. 数据面协议（草案）

最小、面向流、可校验。协议 ID 前缀 `cairn/1`：

| 协议 | 方向 | 作用 |
|---|---|---|
| `/cairn/1/want` | 请求方 → 提供方 | 发一组缺失 CID，请求块 |
| `/cairn/1/chunk` | 双向 | 传块（密文块，逐块可校验） |
| `/cairn/1/head` | 请求方 → 提供方 | 取对象 head 信封（manifest） |
| `/cairn/1/announce` | 双向 | 公告"我有哪些 OID/head"（可选，走 GossipSub） |

流程（**pull 为主**）：

```
A: head(oid)          → 拿到 head 信封
A:  验作者签名 + 验 prev 链
A: 按 manifest 的块表，筛出本地缺失的 CID
A: want([cid...])     → B: chunk(逐块流式回传)
A:  逐块：CID 重算校验 → 落池
```

- **对象即流**：块可分段、并行、断点续传。
- **增量**：CDC 使编辑只产生局部新块，只传变化。
- **校验**：块 CID 重算 + manifest 验签 + `prev` 链。

---

## 4. 传输 / 安全

- 传输：**py-libp2p**（QUIC / TCP / WebSocket）。
- 信道加密：**Noise / TLS**（libp2p 内建）+ 我们已有的内容加密（双重）。
- 身份：复用库身份（Ed25519/X25519），PeerID 由公钥派生。
- 信任：manifest 作者签名是信任根；keyed CID 防止外部确认攻击。

---

## 5. 发现 / NAT

| 场景 | 机制 |
|---|---|
| 同局域网 | **mDNS** |
| 广域网引导 | bootstrap 节点 / rendezvous |
| 大规模路由 | **Kad-DHT** |
| 可达性探测 | **AutoNAT** |
| 直连失败兜底 | **Circuit Relay v2** |
| 打洞升级 | **DCUtR** |
| 公告/订阅 | **GossipSub** |

**诚实边界**：对称 NAT 下打洞失败属常态，必须走中继——这是互联网性质，不是缺陷。

## 6. 选型与成熟度（澄清）

- **协议层成熟**：打洞/中继/探测是 libp2p 标准，go/rust/js 久经考验。
- **Python 绑定**：py-libp2p（MIT/Apache）已过实验期，功能齐全、可用；但未到 go-libp2p 的实战年限。
- **决策**：**先用 py-libp2p**（纯 Python、省心），协议设计不押注具体实现；撞瓶颈再考虑 **go/rust-libp2p 边车 + IPC**。

---

## 7. Server 与 P2P 的关系（优先级）

```
Server（中心化 · 联邦共享）  —— 更底层、优先级更高
   │  天然携带公网节点
   ▼
P2P（去中心化）              —— 由 server 衍生
   └─ relay / bootstrap / 打洞协调 直接复用 server 的公网节点（"白嫖"）
```

- **server 是基础通信**：中心化，但**联邦共享**（多个 server 可互通）。
- **P2P 是衍生**：去中心化，但**不自建打洞节点**——server 的公网节点兼任 relay/bootstrap/rendezvous。
- **共同前提**：先能**互联**，数据底层通信先立住。
- 结论：**server 优先级 ≥ P2P；先做互联与 server，再做 P2P。**

## 8. 分阶段实现

| 阶段 | 目标 | 依赖 |
|---|---|---|
| **P0** | 单节点 server：能被连、按 `want/chunk` 提供块 | 存储层（已就绪） |
| **P1** | 两节点互联同步：head 拉取 + 权限档过滤 | access 层 |
| **P2** | server 作公网节点：bootstrap / Relay / AutoNAT | py-libp2p |
| **P3** | P2P 打洞（DCUtR），复用 server 公网节点 | P2 |
| **P4** | 公告/发现：GossipSub + DHT | P3 |

**先 P0**：不碰公网、不碰 NAT，先证明"内容寻址 + want-list + 互联"这条最小链路。

---

## 9. 隐私边界

- 默认**不广播"我有什么"**；只响应请求。
- 元数据（谁连谁、传多少、何时）仍会泄漏，要藏需上 PIR/洋葱路由——不在本阶段。
- 档位决定可提供范围：私密不对外，公共仅限成员，公开可全网。
