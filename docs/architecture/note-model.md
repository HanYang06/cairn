# 笔记模型（Note Model）

> L3 领域概念规格。回答"笔记到底是什么"，并定死节点 / 基板 / 关系 / 组装四要素。
> 承接内核 [`storage.md`](./storage.md)、[`domains.md`](./domains.md)、[`kernel.md`](./kernel.md)；
> 对象模型 / 基板 / 内存态与存储态见 [`data-model.md`](./data-model.md)。
> 注：**基础数据格式是"基板"，`note` 只是它的一个角色**（`data-model.md` §4.2）。

状态：**草案 v0.2**（正文块列表 / 关系落 DB / 手绘笔画已定；未写代码）

---

## 1. 一句话定义

> **笔记是思考的最小可移动单元，写给未来的自己与相邻的念头。**
> 内容在**基板**里，意义在**关系**里；它是**超文本**，不是文档。

| | 笔记 | 文档（Word） | 文本 |
|---|---|---|---|
| 目的 | 捕捉思考 | 交付成品 | 承载字节 |
| 结构 | 涌现（链接长出来） | 预设（章节分页） | 线性 |
| 生命周期 | 永不完结 | 会完成/发布 | 无身份 |
| 关系 | 对其它笔记（图） | 对读者（呈现） | 对介质 |

**单条笔记没价值，笔记之间的图才是资产。**

---

## 2. 四要素

```
Node      节点   —— 可寻址的最小单位（= 一个内容对象 / OID）
Substrate 基板   —— 节点里装的东西：有序块列表（文本块 + runs / 引用块 / 画板块）
Relation  关系   —— 节点之间的有向边：一等行，落 DB（不再是一个对象）
Composition 组装 —— 一种角色：正文为"对其它节点的排布/引用"的 note → 文档/博客
```

- **没有标题**：标题是显示时算出来的（首行 / 摘要），不是字段。
- **没有正文**："正文"就是基板，无固定模式。
- **没有链接**：链接是**独立的关系行**，不是正文里的语法糖；`[[ ]]` 只是创建关系的一种输入方式。

---

## 3. 身份与全局唯一编码

- 节点身份 = `(author_pubkey, oid)`：**OID 全局唯一 + 作者公钥绑定**，密码学保证。
- 作者绑定：身份 = 一对密钥（Ed25519 签名 + X25519 协商），私钥由主密钥封装存于本库。
- 未来若要绑定"真实用户"，靠身份可携带、可声明（`profile` 节点）实现，不在底层强加。
- **不可篡改性由内容寻址保证**：一个 OID 对应的字节，任何人改不了。

---

## 4. 两种演化模式（关键）

笔记被改变分三类，规则不同：

### 4.1 作者自改（同一节点）

- 原件**必然变更**（head 前进）。
- **保留"一点点版本路径"，不做 git 式全历史**：默认保留**最近 30 天时间窗**内的版本，超出即由 GC 裁剪（`vault.gc(retention_ms=...)` 可调）。
- 对应内核 `seq / prev / author` 版本链。
- **版本只记内容**：只有**基板（正文）变化**才产生新版本（`seq` 前进 + 归档）；标题 / 标签 / `props` 等元数据变更走 `vault.put_meta`，只重签当前 head，不产生历史。
- 30 天保留窗口由 GC 裁剪（`vault.gc(retention_ms=...)`）。

### 4.2 协作修改（同一节点，多人）

- 类似 WPS 共同协作：多人对**同一节点**演进。
- 需要**多作者版本链** + 并发合并。
- **诚实边界**：真正的实时协作（CRDT/OT、冲突合并）是独立难题，**本阶段不做**；模型预留多作者署名，实现后置。

### 4.3 再发布 / 派生（新节点，跨作者）

- 类同开源：基于他人内容升级、引用、改写。
- **生成新节点 + `derived-from` 关系边**，署名派生者。
- **原件不受任何影响**（原件在原作者的库里，别人改不到）。
- 这正是**衍生关系**的来源。

---

## 5. 笔记衍生关系（Provenance DAG）

- 跨作者改写链（张 → 李 → 明 → 红）构成一张**派生 DAG**，与 git commit 图 / 学术引用图同构。
- 每个节点、每条关系**都带作者、都签名**。
- **贡献者** = 沿 DAG 回溯的作者集合。
- **原作者回溯** = 查 `to = 本节点, kind = derived-from` 的传递闭包 → "谁基于我改过"。
- **阅览是隐私**：默认不追踪阅读；读者可**自愿**发 `read` / `endorse` 边，否则无从得知。

## 6. 基板（Substrate）：有序块列表

```
substrate = [ block, ... ]
block ∈ "纯文本"                                   # 默认段落、无样式
      | {kind:"text", block, runs}                 # 有块级类型或行内样式
      | {kind:"ref", oid}                          # 引用另一个对象
      | {kind:"canvas", ...}                       # 内联画板
run   ∈ {t, b, i, u, link, ...}
```

- **文本块**：块级类型（段落 / 标题 / 列表 / 引用 / 代码）+ 行内 runs；**不是 Markdown**，用户从不写语法（WYSIWYG）。
- **引用块（transclusion）**：图 / 视频 / 任意文件 / 别的笔记，以 **OID** 嵌入，二进制本体另存为对象，不内联。
- **画板块**：内联的逻辑图 / 手绘（详细见 [`data-model.md`](./data-model.md) §5.3）。
- 细节（裸串默认、样式"一加就拆 / 一撤就合"、规范化）以 [`data-model.md`](./data-model.md) §5.1 为准。

### 6.1 手绘（sketch）：存原始笔画

- **自由创作必须保真**：sketch 存**笔画折线坐标**，不存栅格图。
- **识别（歪扭 → 标准图元）是可选增强**，不是保存前提——免得识别错一次就丢数据。
- **逻辑图（diagram）不走手绘**：它只存语义（节点 + 边），几何走自动布局（[`data-model.md`](./data-model.md) §5.3）。
- 识别引擎可为设备端小模型（见 §8），作为**单独的增强流程**。

---

## 7. 组装 / 投影（Composition）

- **组装不再是独立格式 / 物种**：它就是"正文里放一堆引用块"的 **note**（一种角色）。
- **文档 = 组装的 note**；**博客 = 公开档里的组装**；渲染是投影。
- 于是"写文档"与"发博客"共用同一模型，只是**可见性档位不同**（私密 / 公共 / 公开）。
- 笔记是原料，文档/博客是投影——直通 P2P 北极星。

## 8. Agent 与 AI

### 8.1 立场

- **AI 不是作者身份，而是一种"使用方式"**：用户通过 AI 调用能力。
- AI 的动作**归因于发起它的用户**（可标注"AI 辅助 / 用了哪个模型"）。
- 因此**不为 AI 单做一套 API**：把内核能力暴露为**可被调用的工具**（MCP / skill），AI 与人都走同一套。

### 8.2 内核能力即工具集

读（`open/iter`）、订阅（`subscribe`）、写（`put`）、建关系——天然就是一批"工具"。AI 接入 = 挂一个 Agent，按需调用这些工具并写回结果。

### 8.3 低能力 AI 与高能力 AI

| | 低能力 AI | 高能力 AI |
|---|---|---|
| 形态 | 自研机器人 / 规则引擎 | 大模型 Agent |
| 用途 | **规则性治理**：用户组合规则形成社区规则 | 帮助写作、整理、复杂治理 |
| 成本 | 低、敏捷 | 看谁有钱 |

- 社区治理是**未来 P2P 社区**的一部分，底层只提供"工具 + 关系"，治理逻辑属上层。

### 8.4 提案（proposal）

- Agent 可先产出**提案**（不落盘），人接受后才成为派生 / 关系。
- 保证"人在环上"，AI 不越权。

## 9. 捕捉面 vs 编辑面（及时性）

念头会过期，所以**捕捉必须零摩擦**：

| | 捕捉面 catch | 编辑面 develop |
|---|---|---|
| 时刻 | 念头一闪 | 坐下来整理 |
| 要求 | 秒开、零成本 | 富、慢一点无妨 |
| 技术 | **原生 Qt、常驻热键** | **Web 富编辑 / 画布**（可预加载） |

- 总体架构：**Qt 外壳（窗口/列表/搜索/热键捕捉/时间轴）+ Web 富编辑画布**，两者分离。
- 首期入口：**从文档（组装）角度切入**——先能"写文档"，再补"闪现捕捉"。

## 10. 与内核的映射

| 概念 | 内核落点 |
|---|---|
| 节点 | 内容对象（`type = cairn.note`），`author` = 身份公钥 |
| 基板 | 对象 payload（CBOR 块列表） |
| 关系 | **DB 行**（`structure.db`）：`src / dst / kind / author / at`（不再是对象） |
| 组装 | 角色：正文为节点引用排布的 note |
| 版本路径 | manifest `seq / prev / author` + 保留策略 |
| 衍生关系 | 对关系表做闭包计算 |

关系类型（草案）：`derived-from`、`edits`、`annotates`、`replies-to`、`references`、`transcludes`、`read`、`endorse`。
